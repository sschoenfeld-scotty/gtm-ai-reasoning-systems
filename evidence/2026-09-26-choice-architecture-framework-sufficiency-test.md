# Choice Architecture Framework Sufficiency Test

*What happened when an explicit choice-architecture check was tested against current Human Pattern 1*

> Structured framework-development evaluation | September 26, 2026  
> Status | Working hypothesis strengthened and narrowed  
> Canonical Full Stack change | None

## Why This Evidence Entry Exists

This test began with a plausible framework-development question.

[Human Pattern 1](../architecture/human-pattern-1.md) already separates observed behavior from stated account and inferred driver. It also tests structural and systemic explanations before personal motive is treated as the leading explanation.

The candidate proposed making one additional area more explicit.

When the design of the available choices could materially shape behavior, should the reasoning inspect what the system made each option mean to the actor at the moment of choice, then keep behavioral effect, institutional benefit, institutional knowledge, tolerance, and intent from collapsing into one another?

The purpose of the test was not to produce a richer behavioral narrative.

The purpose was to determine whether the explicit candidate repeatedly improved diagnosis or decision quality beyond what current Human Pattern 1 already produced.

## Canonical Baseline

At publication time, the live canonical pair identifies as Full Stack v5.1.

Current Human Pattern 1 already requires behavior before motive, a credible alternative when material, structural and systemic inspection, and a decision-dependency test.

That creates a high burden for any proposed addition.

The relevant question is not whether the existing framework can theoretically reach the same conclusion.

The question is whether the candidate improves execution reliability enough to justify added framework complexity.

## Candidate Status Before Testing

The proposed Choice Architecture and Institutional Incentive Check entered the experiment as a **working hypothesis**.

It was not canonical architecture.

The candidate focused on whether the available choice environment itself could predictably shape behavior, and whether the same behavior might emerge even if the actor's underlying preference or motive were different.

The private experiment specification contained more detailed execution wording and evidence-state controls. This public entry preserves the reasoning problem and result without publishing the complete private operating procedure.

## The First Run Was Rejected

The first attempt produced an apparently clean conclusion.

It was not a valid control.

The evaluator had already read the candidate specification before executing the baseline condition. Even if the baseline was instructed to use only current Human Pattern 1 language, the distinction being tested was already present in the evaluator's context.

That contaminated the central comparison.

The initial conclusion was therefore withdrawn rather than protected.

The failed run remains part of the development record because it exposed an evaluation-design problem.

> **A framework-sufficiency test cannot establish that the baseline independently surfaces a distinction if the baseline evaluator has already been shown the distinction.**

## Clean Test Design

The rerun used three fresh Chat contexts.

**Control condition**

Pass A received the live Full Stack v5.1 canonical sources, the frozen case evidence, and current Human Pattern 1. It did not receive the candidate language.

**Experimental condition**

Pass B received the same frozen evidence and reasoning requirements, plus the candidate check.

**Blind adjudication**

A third fresh context received the two completed outputs under neutral labels. It was instructed not to reward additional detail, terminology, length, or polish. It evaluated whether either output materially changed causal diagnosis, confidence, prognosis, strategic adjudication, or action.

This design improved isolation relative to the first run.

It was still not a laboratory-style blinded experiment. The runs occurred on the same platform, shared higher-level product behavior may remain, and the sample contained only four cases.

## Frozen Case Set

| Case | Why it was included |
| --- | --- |
| OpenAI reasoning-level selection | A choice made before task-specific outcome quality is observable |
| Adobe annual-paid-monthly subscription | A consumer design case with alleged disclosure and cancellation asymmetry |
| Amazon Prime and Iliad | A case with stronger evidence of institutional awareness and alleged business-performance tradeoffs |
| Electronic health-record opioid defaults | A randomized operating case where the choice environment itself was experimentally changed |

The fourth case was intentionally different from the consumer cases.

Its randomized design made it possible to separate evidence that the environment caused a behavioral change from uncertainty about the psychological mechanism through which people responded.

## Blind Adjudication Result

### Case 1

**No material difference**

Both conditions identified the same governing issue.

Users make a pre-outcome choice under incomplete information, so the presentation of the options may influence selection independently of a stable underlying preference.

Both conditions also preserved low confidence about actual behavioral effect because no observed selection data was supplied.

The candidate made the attribution boundary more explicit, but it did not change the diagnosis or action.

### Case 2

**Limited confidence-discipline improvement**

Both conditions identified asymmetric enrollment and exit structure and both avoided treating institutional benefit as proof of deliberate deception.

The experimental condition kept confidence in the inferred institutional driver lower.

That was a defensible improvement because general commercial incentives made the hypothesis plausible but did not constitute Adobe-specific causal evidence.

The governing diagnosis and corrective action did not change.

### Case 3

**No material difference**

Both conditions recognized that the evidence was stronger than in the earlier cases because the frozen packet included internal awareness plus allegations that corrective changes were affected by business-performance consequences.

Both increased confidence relative to an interface-only inference while stopping short of treating deliberate exploitation as proven.

The candidate produced cleaner evidence-state labels, but the baseline already captured the operative distinction.

### Case 4

**Material reasoning improvement**

Both conditions correctly concluded that the electronic prescribing default changed behavior.

The material difference concerned confidence.

The baseline reduced confidence in the inferred driver because the evidence did not distinguish passive default acceptance from perceived institutional guidance.

The experimental condition separated two different questions.

The randomized evidence supported high confidence that the designed environment was a causal driver of the behavioral change.

The psychological mechanism through which clinicians responded remained uncertain.

That distinction mattered.

Uncertainty about the actor's internal mechanism should not automatically reduce confidence in an experimentally demonstrated environmental cause.

The recommended action remained broadly similar, but the evidentiary calibration improved.

## Cross-Case Result

The candidate did not repeatedly change the governing diagnosis, prognosis, strategic adjudication, or recommended action.

Cases 1 and 3 were substantially equivalent.

Case 2 produced a smaller attribution-discipline improvement.

Case 4 produced one clear material reasoning improvement.

That is not enough evidence to promote the candidate into canonical Full Stack.

It is also too much evidence to dismiss the candidate as having no incremental value.

## Narrowed Working Hypothesis

The broad candidate can now be narrowed.

The strongest unresolved question is not whether Full Stack needs a general choice-architecture layer.

It is whether Human Pattern 1 reliably distinguishes between

**confidence that a designed environment caused a behavioral change**

and

**confidence in the actor's internal psychological mechanism for responding to that environment**

Case 4 suggests that those confidence judgments can diverge.

The current framework may already contain enough structure to make that distinction. This experiment does not establish that it produces the distinction reliably.

## Framework Disposition

### Full Stack v5.1

**No canonical change**

The candidate did not clear the repeatability and non-duplication burden required for framework modification.

### Human Pattern 1

**No canonical change**

The existing architecture already handled most of the tested distinctions.

One case exposed a possible execution gap worth preserving as a working hypothesis.

### Behavioral Inference Engine

**No canonical change**

This experiment tested current-case behavioral reasoning rather than longitudinal persistence or revision.

### Candidate

**Working hypothesis strengthened and narrowed**

The candidate remains outside canonical architecture.

## What This Test Does Not Establish

This test does not establish that an explicit choice-architecture check generally improves Full Stack.

It does not establish that the candidate should become a new peer stage or permanent nested check.

It does not establish institutional motive in any of the cases.

It does not establish that the observed Case 4 difference would replicate across models, users, or future cases.

It does not convert a four-case fresh-context comparison into formal validation.

## Process Lesson

The first failed run became part of the evidence.

The development discipline mattered more than defending the initial conclusion.

A plausible refinement was proposed. The first test was found to be contaminated. The conclusion was withdrawn. The test was redesigned. The cleaner result was mixed.

That is useful framework-development evidence.

> **A candidate should not survive because it is elegant. It should survive because it repeatedly changes reasoning that the existing architecture does not already handle.**

## Current Disposition

Preserve this experiment as public framework-development evidence.

Leave Full Stack v5.1 and Human Pattern 1 unchanged.

Keep the narrowed distinction as a working hypothesis.

Reopen the question only if later real cases independently expose the same execution gap.
